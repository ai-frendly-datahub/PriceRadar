# PriceRadar - 제품 요구사항 정의 (PRD)

## 1. 제품 개요

### 비전
여러 쇼핑몰의 가격 변동을 한눈에 파악하고, **지금 사야 할 상품**을 레이다 형태로 제공하는 가격 추적 시스템

### 목표
- 폴센트(Fallcent) 등의 소스에서 가격 정보를 자동 수집
- 4가지 축(할인 강도, 타이밍 희소성, 인기도, 안정성)으로 상품 스코어링
- 구매 타이밍이 좋은 상품을 우선순위로 제공
- 일일 HTML 리포트 자동 생성

## 2. 핵심 기능

### 2.1 가격 데이터 수집
- **입력**: 폴센트 웹페이지 (최저가, 카테고리별 급락, 인기 상품)
- **출력**: RawItem (상품명, 현재가, 평균가, 할인율 등)
- **주기**: 1일 1회 (확장 가능)

### 2.2 가격 스코어링
4가지 축으로 구매 타이밍 점수 계산:

1. **할인 강도 (40%)**
   - 현재가 vs 평균가
   - 현재가 vs 정가
   - 할인율

2. **타이밍 희소성 (30%)**
   - 90일 내 최저가 여부
   - 가격 히스토리 분석

3. **인기도 (20%)**
   - 인기 상품 태그
   - 핫딜 태그

4. **가격 안정성 (10%)**
   - 가격 변동성 (표준편차 / 평균)
   - 낮을수록 좋음

**최종 점수**: 0.0 ~ 1.0 (높을수록 좋음)

### 2.3 카테고리별 조회
- 식품, 생활용품, 가전/디지털, 뷰티 등
- 카테고리별 상위 N개 딜 제공

### 2.4 HTML 리포트 생성
- 일일 리포트 자동 생성
- 카드 형식으로 상품 표시
- 레이다 점수 시각화 (진행 바)
- GitHub Pages 배포

## 3. 사용자 시나리오

### 시나리오 1: 일일 딜 확인
1. 사용자가 매일 아침 리포트 페이지 방문
2. 레이다 점수 상위 20개 상품 확인
3. 관심 있는 상품 클릭 → 쇼핑몰 이동
4. 구매 결정

### 시나리오 2: 카테고리별 탐색
1. 사용자가 "가전" 카테고리 선택
2. 가전 제품 중 점수 높은 상품 확인
3. 가격 히스토리 그래프 확인
4. 구매 타이밍 판단

### 시나리오 3: 관심 상품 알림
1. 사용자가 특정 상품을 워치리스트에 추가
2. 해당 상품의 점수가 0.8 이상이 되면 알림
3. 사용자가 알림 확인 후 구매

## 5. KPI 및 성공 지표

### 5.1 시스템 안정성
- **일일 수집 성공률**: ≥ 95%
- **리포트 생성 성공률**: ≥ 95%

### 5.2 데이터 품질
- **상품 수**: ≥ 100개/일
- **카테고리 커버리지**: 전 카테고리 활성
- **결측 데이터**: ≤ 2%

### 5.3 사용자 가치
- **상위 딜 점수**: 평균 ≥ 0.7
- **리포트당 카드 수**: ≥ 10개

## 6. 제약사항

### 6.1 기술적 제약
- Python 3.11 이상
- DuckDB 파일 기반 저장 (확장성 고려)
- 크롤링 주기: 1일 1회 (트래픽 부하 고려)

### 6.2 법적/윤리적 제약
- 폴센트 웹사이트 이용 약관 준수
- robots.txt 확인
- 적절한 User-Agent 사용
- 요청 간 딜레이 (최소 1초)

### 6.3 데이터 제약
- 실시간 가격 변동은 반영하지 않음 (1일 1회 스냅샷)
- 쿠폰/카드 할인은 폴센트 데이터에 의존
